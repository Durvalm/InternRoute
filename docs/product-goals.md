# Product Goals

## Product mission
Help CS students become internship-ready and convert that readiness into at least one strong internship offer.

## Core user outcome
- A student can move from unclear prep to a clear path with measurable progress.
- The platform should answer: what to do now, why it matters, and whether the user is improving.

## North-star outcome
- Internship conversion: users who start the core flow and eventually report interview activity and/or offers.

## Practical goals for current product phase
1. Make progression logic explicit and predictable.
2. Keep module completion and readiness scoring consistent.
3. Keep timeline advice aligned with real hiring windows.
4. Reduce user confusion about what "ready" means.
5. Improve retention via a repeatable weekly workflow.

## Operating principles
- Clarity over cleverness: clear thresholds and deterministic module rules.
- Speed over perfection: users should execute quickly once they meet minimum signal.
- Data-driven iteration: changes should be validated with measurable behavior shifts.

## Success metrics to monitor
- Activation: account created -> onboarding completed -> first core module action.
- Core progression: users reaching Intro 100%, Coding 100%, Projects 80%, Resume 80%, Applications 100%.
- Readiness movement: median delta in readiness score over 14 and 30 days.
- Retention: D1 / D7 / D30 active-day return rates.
- Conversion proxy: applications module completion and interview-prep engagement.

## Guardrails
- Do not silently change thresholds.
- Do not add module gates without documenting the reason and migration impact.
- Keep UI language consistent with backend logic (especially seasonal/timeline messaging).
